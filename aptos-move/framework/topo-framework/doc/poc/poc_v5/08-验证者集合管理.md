# 08 — 验证者集合管理

本文档详细分析验证者的加入/离开流程、投票权重计算、活性回退机制。

**源文件**：`stake.move:892-958, 966-1022, 1198-1355`

## 8.1 验证者生命周期总览

```mermaid
stateDiagram-v2
    [*] --> 未注册

    未注册 --> INACTIVE: initialize_stake_owner<br/>+ register_validator
    INACTIVE --> PENDING_ACTIVE: join_validator_set
    PENDING_ACTIVE --> ACTIVE: on_new_epoch（阶段4）
    ACTIVE --> PENDING_INACTIVE: leave_validator_set
    PENDING_INACTIVE --> INACTIVE: on_new_epoch（阶段4）

    ACTIVE --> INACTIVE: on_new_epoch（阶段5）<br/>voting_power < minimum_stake

    note right of ACTIVE: 出块、投票、赚取奖励
    note right of PENDING_INACTIVE: 仍可投票，仍赚奖励<br/>下个 epoch 退出
```

## 8.2 加入验证者集合

### 前置条件

```mermaid
flowchart TD
    A["join_validator_set(operator, pool_address)"] --> B{allow_validator_set_change?}
    B -->|否| ERR1["abort ENO_POST_GENESIS_VALIDATOR_SET_CHANGE_ALLOWED"]
    B -->|是| C{重配置进行中?}
    C -->|是| ERR2["abort ERECONFIGURATION_IN_PROGRESS"]
    C -->|否| D{StakePool 存在?}
    D -->|否| ERR3["abort ESTAKE_POOL_DOES_NOT_EXIST"]
    D -->|是| E{caller == operator?}
    E -->|否| ERR4["abort ENOT_OPERATOR"]
    E -->|是| F{当前状态 == INACTIVE?}
    F -->|否| ERR5["abort EALREADY_ACTIVE_VALIDATOR"]
    F -->|是| G[检查算力]
```

### 算力检查

```mermaid
flowchart TD
    G[检查算力] --> H["self_power = get_validator_joining_power()"]
    H --> I{self_power > 0?}
    I -->|否| ERR6["abort ESTAKE_TOO_LOW<br/>（owner 必须自委托）"]
    I -->|是| J["voting_power = get_validator_total_power()"]
    J --> K{voting_power >= minimum_stake?}
    K -->|否| ERR7["abort ESTAKE_TOO_LOW"]
    K -->|是| L{voting_power <= maximum_stake?}
    L -->|否| ERR8["abort ESTAKE_TOO_HIGH"]
    L -->|是| M[检查投票权增长限制]
    M --> N{consensus_pubkey 非空?}
    N -->|否| ERR9["abort EINVALID_PUBLIC_KEY"]
    N -->|是| O{集合大小 <= 65536?}
    O -->|否| ERR10["abort EVALIDATOR_SET_TOO_LARGE"]
    O -->|是| P[加入 pending_active 队列]
    P --> Q[设置状态 PENDING_ACTIVE]
    Q --> R[emit JoinValidatorSet]
```

### 投票权增长限制

```move
fun update_voting_power_increase(new_voting_power: u64) {
    let validator_set = borrow_global_mut<ValidatorSet>(@topo_framework);
    let voting_power_increase_limit =
        staking_config::get_voting_power_increase_limit(&staking_config::get());
    validator_set.total_joining_power += (new_voting_power as u128);

    // 检查新加入的总投票权不超过当前总投票权的 limit%
    assert!(
        validator_set.total_joining_power
            <= validator_set.total_voting_power * (voting_power_increase_limit as u128) / 100,
        EVOTING_POWER_INCREASE_EXCEEDS_LIMIT
    );
}
```

这防止单个 epoch 内大量新验证者涌入导致投票权剧烈变化。

## 8.3 离开验证者集合

```mermaid
sequenceDiagram
    participant OP as Operator
    participant ST as stake.move
    participant SR as staking_registry

    OP->>ST: leave_validator_set(pool_address)
    ST->>ST: 校验 operator 身份

    alt 验证者在 pending_active 中
        ST->>ST: 从 pending_active 移除
        ST->>ST: 减少 total_joining_power
        ST->>SR: set_validator_inactive(pool_address)
        Note over ST: 直接变为 INACTIVE<br/>（还没正式激活，直接撤回）
    else 验证者在 active_validators 中
        ST->>ST: 从 active_validators 移除
        ST->>ST: 校验不是最后一个验证者
        ST->>ST: 加入 pending_inactive
        ST->>SR: set_validator_pending_inactive(pool_address)
        ST->>ST: emit LeaveValidatorSet
        Note over ST: 本 epoch 仍可投票和赚奖励<br/>下个 epoch 正式退出
    end
```

**关键规则**：
- 最后一个活跃验证者不能离开（`ELAST_VALIDATOR`）
- pending_active 的验证者可以直接撤回（不经过 pending_inactive）
- pending_inactive 的验证者在本 epoch 仍然参与共识和奖励

## 8.4 投票权重计算

### 当前 Epoch 投票权

```move
public fun get_current_epoch_voting_power(pool_address: address): u64 {
    let validator_state = get_validator_state(pool_address);
    if (validator_state == ACTIVE || validator_state == PENDING_INACTIVE) {
        staking_registry::get_validator_total_power(pool_address)
    } else {
        0
    }
}
```

投票权 = 验证者所有委托者的 `effective_power` 之和。

### 下一 Epoch 投票权预测

```move
fun compute_simulated_validator_info(candidate, ...): (u64, ValidatorInfo) {

        staking_registry::get_validator_total_power_for_next_epoch(candidate.addr);

```

`get_validator_total_power_for_next_epoch` 额外考虑：

## 8.5 验证者集合重建（阶段 5 详解）

### 重建流程

```mermaid
flowchart TD
    A[遍历 active_validators] --> B["generate_validator_info(pool_address)"]
    B --> C["voting_power = get_validator_total_power()"]
    C --> D{"voting_power >= minimum_stake?"}

    D -->|是| E[加入 next_epoch_validators]
    E --> F["total_voting_power += voting_power"]

    D -->|否| G[加入 dropped_validators]

    H{next_epoch_validators 非空?}
    E --> H
    G --> H

    H -->|是| I[正常路径]
    I --> J[dropped_validators → INACTIVE]
    J --> K[更新 active_validators]

    H -->|否| L[活性回退路径]
    L --> M[保留旧 active_validators]
    M --> N[重新计算每个验证者的 voting_power]
    N --> O[emit ValidatorSetLivenessFallback]
```

### 正常路径

```move
if (!next_epoch_validators.is_empty()) {
    dropped_validators.for_each_ref(|addr| {
        staking_registry::set_validator_inactive(*addr);
    });
    validator_set.active_validators = next_epoch_validators;
    validator_set.total_voting_power = total_voting_power;
}
```

### 活性回退路径

```move
if (next_epoch_validators.is_empty()) {
    // 保留旧验证者集合，刷新投票权
    let refreshed_validators = vector::empty();
    let emergency_total_voting_power = 0u128;
    // 遍历旧 active_validators，重新生成 ValidatorInfo
    // ...
    validator_set.active_validators = refreshed_validators;
    validator_set.total_voting_power = emergency_total_voting_power;

    event::emit(ValidatorSetLivenessFallback {
        minimum_stake,
        emergency_validator_count: validator_set.active_validators.length(),
        total_emergency_voting_power: validator_set.total_voting_power,
    });
}
```

**活性回退的触发条件**：所有验证者的 `voting_power` 都低于 `minimum_stake`。

**设计意图**：宁可让不合格的验证者继续出块，也不能让链停机。

## 8.6 后续处理

### 更新 validator_index

```move
let validator_index = 0;
while (validator_index < vlen) {
    let validator_info = validator_set.active_validators.borrow_mut(validator_index);
    validator_info.config.validator_index = validator_index;
    let validator_config = borrow_global_mut<ValidatorConfig>(validator_info.addr);
    validator_config.validator_index = validator_index;
    // ...
    validator_index += 1;
}
```

每个验证者的 `validator_index` 在每个 epoch 重新分配，用于：
- 交易费记录（`record_fee` 按 index 累积）
- 性能统计（`ValidatorPerformance` 按 index 索引）

## 8.7 Operator 与 Owner 的分离

```mermaid
graph LR
    subgraph "Owner（所有者）"
        O1[拥有 OwnerCapability]
        O2[可以 set_operator]
        O3[可以 increase_lockup]
        O4[在 staking_registry 中注册]
    end

    subgraph "Operator（运营者）"
        P1[rotate_consensus_key]
        P2[update_network_addresses]
        P3[join_validator_set]
        P4[leave_validator_set]
    end

    O1 -->|"授权"| P1
    O1 -->|"授权"| P2
    O1 -->|"授权"| P3
    O1 -->|"授权"| P4
```

Owner 和 Operator 可以是不同地址：
- Owner 控制经济权益（质押、委托、提取）
- Operator 控制运营操作（共识密钥、网络地址、加入/离开集合）
- Owner 可以随时更换 Operator

## 8.8 共识密钥轮换

```move
public entry fun rotate_consensus_key(
    operator: &signer,
    pool_address: address,
    new_consensus_pubkey: vector<u8>,
    proof_of_possession: vector<u8>,
)
```

- 需要 BLS proof-of-possession 防止 rogue-key 攻击
- 下个 epoch 生效（写入 `ValidatorConfig`，在 `on_new_epoch` 中被读取）
- 不能在重配置进行中执行

## 8.9 验证者集合大小限制

| 参数 | 值 | 说明 |
|------|-----|------|
| `MAX_VALIDATOR_SET_SIZE` | 65536 | 硬上限，受 bitvec 限制 |
| `minimum_stake` | 创世配置 | 最低投票权要求 |
| `maximum_stake` | 创世配置 | 最高投票权限制 |
| `voting_power_increase_limit` | 创世配置 | 每 epoch 新增投票权上限（%） |
