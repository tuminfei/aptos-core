# 13 — 共识测试框架设计

本文档重新定义 PoC 共识修改的测试框架。

这次优化后的核心结论只有一句：

**真正的 PoC 端到端测试，只应覆盖主链路状态机；治理和创世更多是接缝回归，不应一股脑外置成独立 e2e 文件。**

也就是说，测试框架需要同时满足两点：

1. 主链路场景要从 `stake.move` 内嵌测试中拆出来，形成独立 `tests/*.move` 测试模块。
2. 但不是所有“跨模块”场景都应该算成外置 e2e；`genesis` / `topo_governance` 这类更适合作为模块内接缝测试保留在源文件附近。

---

## 13.1 本次完整测试真正要覆盖什么

### 1. 主链路状态机

这是本次测试的主体：

- validator 注册、加入、离开
- delegator deposit / delegate / undelegate / withdraw
- `on_new_epoch()` 编排
- period 推进、retention、生效时机
- reward / fee / force undelegate
- validator set 重建与 fallback

### 2. 接缝正确性

这是次级目标：

- `genesis.move` 是否把 PoC 初始化接好
- `topo_governance.move` 是否读取 live PoC power
- Rust 是否仍能正确消费 `ValidatorSet` / `NewEpoch`

### 3. 不属于本次完整测试

- 多节点网络一致性
- Rust `consensus/` 协议算法
- forge 大集群

---

## 13.2 重新划分测试类型

当前设计里最大的问题，是把三种不同性质的测试混成了“端到端”。

优化后应明确分成三类：

### A. 模块内局部语义测试

宿主：

- `poc_power_store.move`
- `staking_registry.move`

目标：

- 单模块公式、错误码、边界行为

### B. 主链路外置 e2e 测试

宿主：

- `aptos-framework/tests/poc_consensus_e2e.move`
- `aptos-framework/tests/poc_consensus_epoch_e2e.move`

目标：

- 覆盖真实主链路生命周期
- 验证跨 `poc_power_store` / `staking_registry` / `stake` 的主状态机

### C. 模块内接缝回归测试

宿主：

- `genesis.move`
- `topo_governance.move`
- Rust `e2e-move-tests`

目标：

- 验证 PoC 与创世、治理、Rust 消费端的接口接缝

这里的关键纠偏是：

- `genesis` / `topo_governance` 虽然跨模块，但不应默认外置成独立 e2e 文件
- 它们更像“边界接缝回归”，不是主链路场景宿主

---

## 13.3 为什么不能把 e2e 文件拆得过碎

上一版文档把 e2e 文件拆成：

- lifecycle
- epoch transition
- validator set
- governance
- genesis

这个拆法看起来清晰，但对当前仓库并不合理。

### 问题一：测试基建会反向膨胀

每多一个外置文件，就要多一层：

- helper 组合
- signer 参数组织
- 通用断言
- `TEST_FILTER` 维护

对于 PoC 这种强耦合状态机，拆得过细只会让公共测试脚手架膨胀。

### 问题二：会逼出过宽 `#[test_only]` 接口

如果 `genesis` / `governance` 也都外置：

- 就需要把私有初始化和 proposal helper 大量公开
- 这会把模块内部测试辅助函数演化成公开测试 API

这不是“最小测试接口”，而是在为文档拆分买单。

### 问题三：主链路场景本来就高度耦合

以下内容本来就是一个系统：

- validator lifecycle
- epoch transition
- validator set rebuild

把它们拆成太多文件，场景之间会重复初始化、重复造 validator、重复推进 epoch。

结论：

**主链路外置 e2e 只保留 2 个文件最合理，而不是 5 个。**

## 13.4 推荐的最终目录结构

```text
aptos-move/framework/aptos-framework/
├── sources/
│   ├── stake.move
│   ├── genesis.move
│   ├── topo_governance.move
│   ├── poc/poc_power_store.move
│   └── poc/staking_registry.move
└── tests/
    ├── poc_test_utils.move
    ├── poc_consensus_e2e.move
    └── poc_consensus_epoch_e2e.move
```

Rust 侧保持：

```text
aptos-move/e2e-move-tests/src/tests/
└── poc_consensus.rs
```

### 各文件职责

#### `poc_test_utils.move`

- 统一测试 helper
- 不放具体用例

#### `poc_consensus_e2e.move`

- 主生命周期
- validator / delegator 进入、退出、提取
- validator set 变化

#### `poc_consensus_epoch_e2e.move`

- 顺序敏感场景
- reward / fee / force undelegate / next epoch voting power
- fallback

#### `genesis.move`

- 保留 PoC 初始化接缝测试

#### `topo_governance.move`

- 保留 live power / threshold / vote 权限接缝测试

## 13.5 真实测试职责划分

### `poc_power_store.move`

只测：

- staged update
- current / next period 读取
- retention
- operator 权限
- genesis-only 写保护

不测：

- delegator 生命周期
- validator set
- governance

### `staking_registry.move`

只测：

- effective power
- delegate / undelegate / withdraw
- cooldown
- 局部 reward / fee / commission 语义

不测：

- 完整 epoch 编排
- validator set rebuild

### `stake.move`

仍是主编排模块，但不是最终场景文档宿主。

它负责：

- 提供主链路测试 helper
- 提供 epoch 驱动能力
- 提供 validator set 读接口

### `genesis.move`

只测接缝：

- PoC 初始化是否接好
- cooldown floor 是否正确
- 创世 validator 是否被首轮激活

### `topo_governance.move`

只测接缝：

- proposal threshold 是否读 live total power
- voter power 是否实时变化
- force undelegate 后 voting power 是否归零

### Rust

只测：

- `ValidatorSet::fetch_config(...)`
- `ContractEvent::is_new_epoch_event()`

---

## 13.6 哪些场景才算“外置 e2e”

必须满足两个条件，才值得放到 `tests/*.move`：

1. 它是主链路场景，而不是模块边界接缝。
2. 它需要跨多个模块跑完整状态机，而不是只验证某个边界值。

按这个标准：

### 应外置

- 新 validator 从零加入
- delegator 完整生命周期
- reward 与 force undelegate 时序
- pending_inactive 最后一轮奖励
- validator set 剔除与 fallback
- next epoch voting power 预测

### 不应默认外置

- `ensure_poc_staking_initialized` 幂等
- cooldown 取 `max(lockup, voting_duration)`
- proposal 阈值读取 live total power
- force undelegate 后治理权失效

这些不是不重要，而是更适合待在 `genesis.move` / `topo_governance.move` 的接缝测试里。

## 13.7 最小 `#[test_only]` 接口策略

这部分必须比上一版更收紧。

### 13.7.1 原则

只在以下情况新增 `#[test_only] public`：

- 外部 `tests/*.move` 真正无法通过现有公开接口完成主链路场景
- 且该接口只是正式逻辑的薄包装，不引入测试专用分支

### 13.7.2 当前已足够复用的接口

#### `stake.move`

- `initialize_for_test`
- `initialize_for_test_custom`
- `initialize_test_validator`
- `mint_and_add_stake`
- `generate_identity`
- `end_epoch`
- `get_validator_state`
- `get_validator_index`
- `cur_validator_consensus_infos`
- `next_validator_consensus_infos`

#### `staking_registry.move`

- `deposit`
- `delegate`
- `undelegate`
- `withdraw_deposit`
- `get_effective_power`
- `get_total_staked_power`
- `get_user_stake_info`
- `get_validator_total_power`
- `get_cooldown_secs`
- `set_active_power_thresholds`

#### `poc_power_store.move`

- `set_genesis_committed_power`
- `stage_batch_update`
- `set_retention_bps_per_period`
- `get_current_period`
- `get_user_committed_power`

### 13.7.3 真正建议新增的接口

只保留 `stake.move` 两个候选：

- `#[test_only] public fun set_validator_performance_for_test(validator_index: u64, successful: u64, failed: u64)`
- `#[test_only] public fun record_fee_for_test(vm: &signer, validator_indices: vector<u64>, fee_amounts: vector<u64>)`

原因：

- 主链路外置 e2e 如果不具备这两个能力，就很难稳定构造 reward / fee / next-epoch 预测场景
- 这两个接口都是对现有正式逻辑的薄包装

### 13.7.4 不再建议外置后补的接口

以下接口从“建议新增”改为“不建议为了文档拆分而新增”：

- `topo_governance::initialize_for_test(...)`
- `topo_governance::create_proposal_for_test(...)`
- `genesis::ensure_poc_staking_initialized_for_test(...)`
- `genesis::create_initialize_validators_with_commission_for_test(...)`

原因：

- 它们主要服务于接缝测试，不是主链路外置 e2e 刚需
- 把这些私有 helper 公开，会显著放大测试 API 面
- 更好的做法是：接缝测试继续留在 `genesis.move` / `topo_governance.move` 模块内

## 13.8 推荐执行顺序

### 1. 模块内局部语义

```bash
env TEST_FILTER=poc_power_store cargo test -p aptos-framework move_framework_unit_tests -- --nocapture
env TEST_FILTER=force_undelegate cargo test -p aptos-framework move_framework_unit_tests -- --nocapture
```

### 2. 主链路外置 e2e

```bash
env TEST_FILTER=poc_consensus_e2e cargo test -p aptos-framework move_framework_unit_tests -- --nocapture
env TEST_FILTER=poc_consensus_epoch_e2e cargo test -p aptos-framework move_framework_unit_tests -- --nocapture
```

### 3. 接缝回归

```bash
env TEST_FILTER=governance cargo test -p aptos-framework move_framework_unit_tests -- --nocapture
env TEST_FILTER=genesis cargo test -p aptos-framework move_framework_unit_tests -- --nocapture
```

### 4. Rust 薄契约

```bash
cargo test -p e2e-move-tests poc_consensus -- --nocapture
```

## 13.10 最终结论

优化后的测试框架不再追求“把所有重要场景都变成独立 e2e 文件”，而是追求：

1. 主链路状态机外置成少量高价值 `tests/*.move` 文件。
2. `genesis` / `topo_governance` 继续作为模块内接缝回归宿主。
3. `#[test_only]` 接口只为主链路外置 e2e 暴露最小编排能力。

这样设计，才既符合当前仓库结构，又不会为了测试分层把业务模块暴露成一堆测试后门。
